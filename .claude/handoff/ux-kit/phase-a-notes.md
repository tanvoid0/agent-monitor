## Deviations
- MenuButton `label` is optional (spec: required string) and defaults to t("common:ui.openMenu") — the orchestrator said MenuButton needs that key; Clickable's `menuLabel` just passes through.
- IconButton gained `to?: string` (renders a react-router Link via Button's Slot path) — needed so PageHeader `back` string can render the back IconButton as a link without a second code path; not in the spec's IconButton prop list.
- Clickable's inner-control ignore selector adds `[role=menu]` to the spec's list (`a,button,input,select,textarea,[role=button],[role=menuitem]`) — without it a click on a portalled menu Label/Separator (which have no menuitem role) bubbles through the React tree and triggers the row navigation.
- Clickable's native-passthrough (shift+right-click / active text selection) is implemented with an `onContextMenuCapture` that calls `e.stopPropagation()` before Radix's bubble-phase Trigger handler runs, rather than toggling the Trigger's `disabled` prop (a prop cannot be decided at event time). Verified by test: shift+contextmenu opens no menu and the native default is not prevented.
- Clickable handles middle-click via `onAuxClick` (browsers fire `auxclick`, not `click`, for button 1); the `click` path still checks `e.button === 1` as the spec wrote it.
- Tabs selected/unselected styling is chosen via a small React context set by TabsList (`variant`) so TabsTrigger needs no extra prop; data-[state=active] classes carry the selected look.
- PageHeader icon uses `w-[18px] h-[18px]` (Tailwind 3.4 has no `w-4.5`), per the spec's fallback. PageHeader only wraps in an outer `flex flex-col gap-3` when `children` (second row) is present; otherwise the spec's exact `flex flex-wrap items-center justify-between gap-3` row is the root element.
- Button default variant is `secondary` / size `md` (spec did not name defaults).
- The Tabs arrow-key test awaits `waitFor` because Radix roving-focus moves focus in a `setTimeout`; automatic activation then follows the focus.

## Deviations
- Session/agent default labels use `||` (SessionDetail.tsx:663 pattern: `session.name || …`) rather than the spec's `??`, so an empty-string name falls back to `Session <id>` / type / id instead of rendering blank. - `mono` defaults to true (the spec's exact class list has `font-mono text-[11px]` unconditionally and also lists `mono?: boolean`; `mono={false}` drops both classes so callers can render prose names in the surrounding font). - `EntityMenuCtx.openCwd` is typed `(cwd) => Promise<unknown>` (spec: `Promise<void>`) so `api.sessions.openCwd` (returns `Promise<{ok, cwd}>`) can be the default without a wrapper; `(ctx.openCwd ?? api.sessions.openCwd)(cwd)` is evaluated inside onSelect, so tests that mock `../../lib/api` without openCwd still import fine.
